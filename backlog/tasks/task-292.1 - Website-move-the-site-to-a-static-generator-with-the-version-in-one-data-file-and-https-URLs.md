## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The feature pages (TASK-292) add twenty-odd pages that share a nav, footer, download button and version. Hand-written HTML will drift. scripts/publish-release.sh also rewrites the version, links and size in index.html with a Python regex and bumps the sitemap lastmod, which does not scale past one page. Planning leaned to Eleventy or Astro (Markdown per feature with frontmatter for the title tag, description, Arc comparison and FAQ; zero client JS); the worker picks after looking at both.

The canonical link, og:url, og:image, sitemap and robots.txt all use http://detourbrowser.com, which tells search engines the http URL is the real one.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Astro 7.4 (user's choice, Nov 7 2026) in ../detour-website, Node pinned in .nvmrc to 24.22.1 (the user uses nvm.fish; Astro 7.4.2+ needs Node >= 22.23.4, the Homebrew default is 22.22.3). compressHTML: false so the home page keeps its whitespace (Astro 7 defaults to JSX whitespace rules).
2. Base layout (head meta: title, description, https canonical/OG/Twitter from site + path) with Nav, Footer and AppIcon components; home page body moved to src/pages/index.astro; asset paths root-absolute so subpages can share them; JSON-LD built from data.
3. src/data/release.json holds version, DMG size and release date; every download link, the version pill, size lines and the schema read it.
4. sitemap.xml generated by an endpoint from the pages under src/pages; robots.txt points at the https sitemap.
5. wrangler.jsonc serves dist/; .gitignore node_modules, dist, .astro; README covers build, dev and wrangler preview.
6. publish-release.sh: write release.json instead of regex-editing index.html; build in the git-archive export (npm ci + astro build with the .nvmrc Node from nvm.fish's folder) before wrangler deploy; dry run builds but does not deploy.
7. Verify: diff built index.html against the old one (only intended changes), compare in Chrome at desktop and phone widths, dry run of the release script website step.
8. http -> https redirect: the site answers http with a 200 today; this is the Cloudflare zone's Always Use HTTPS setting (user's dashboard), not something the static assets can do.
