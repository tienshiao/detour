# Playbooks

* [Build and test](build-and-test.md) - How to generate the project, build, and run the test suite without clobbering another build, another test run or the machine's memory.
* [Debug harness](debug-harness.md) - How to drive and observe the running app from a temporary, environment-gated block in AppDelegate — the pattern, the seeding calls, the stub drag info, and how to keep it out of commits.
* [Diagnosing extension problems](diagnosing-extension-problems.md) - A symptom-to-cause table for Web Extension failures seen in Detour (dead popups, worker restarts, helper CPU, missing content scripts, log noise), with the first check for each and where the mechanism is explained.
* [In-process UI automation](in-process-ui-automation.md) - How to click, type, swipe, switch appearance and capture views from inside the running app, what only external input can do, and why a locked screen silently breaks all of it.
* [Parallel agent workflow](parallel-agent-workflow.md) - How several agents work on this repository at once without breaking each other — one worktree, build directory and test data directory each, one build at a time, explicit review targets, and integration through a branch a person merges.
* [Reading runtime logs](reading-runtime-logs.md) - Unified log recipes for Detour and its WebKit helper processes — categories, predicates, which process logs what, how to read extension console output, and the traps that produce false hits or empty results.
* [Release and website](release-and-website.md) - How a signed, notarized Detour DMG is built and published through Sparkle, and how the website's screenshots and feature loops are captured from a staged demo profile.
* [Runtime verification](runtime-verification.md) - How to build, launch and observe Detour in an isolated profile (the /verify skill), including how to be sure the app you launched is the build you just made.
* [Seeding extensions](seeding-extensions.md) - How to put an extension into an isolated Detour profile by hand for a runtime check — the files, the database rows (including the permission rows a real install writes), a fake native host, and readable worker console output.
* [Signed-build verification](signed-build-verification.md) - How to check extension behaviour that only works in the signed build installed in /Applications (real 1Password, native messaging trust) — deploy, capture the log, drive the session with a person, and read the result.
* [Test host crashes](test-host-crashes.md) - What to do when xcodebuild prints TEST FAILED although no test failed — the test host crashed — and how to get the stack and find the suite that really caused it.
* [UI probes](ui-probes.md) - Measurements to paste into a debug harness when clicks do not land, a window edge will not resize, or keyboard focus is somewhere unexpected — hit-test maps, resize-region probes, first-responder and key-view loop dumps, layout gaps.
* [WebKit helper diagnostics](webkit-helper-diagnostics.md) - How to attribute CPU in a WebKit helper process (Networking, WebContent, GPU) to a site, a service worker or an extension without a debugger, using sample, lsof, the on-disk origin directories and the log.
